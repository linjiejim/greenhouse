# v2 路线图

更新 2026-10-13 · 配套 [PRD §11](prd.md#11-里程碑)、[功能清单](features.md)、[数据模型](data-model.md)

## 分支与节奏

- 先合并 PR #64（表格 → 应用），v2 在它之上开始。由 Jim 合并。
- 合并后给 v1 打最终标签，从它拉出 `release/v1`，只收安全和严重缺陷修复。现有部署（green.linjiejim.com、私有 overlay）留在 v1，直到它们决定迁移。
- v2 在长期分支 `v2` 上进行。每个切片单独开 PR 合进 `v2`；切片完成后在功能清单里把状态改为「已实现」或「已删」，并写上 PR。
- v2 从零建表，所以 `v2` 分支上不需要保持 v1 能跑：旧 Web、旧路由、旧表随对应切片直接删除。移动端、扩展、桌面在 M4 之前不参与 `v2` 分支的类型检查。
- v2.0 发布时 `v2` 合回 `main`。预览环境用空库重建；需要历史数据的部署等迁移工具（M5）。
- 每个切片的门槛：`pnpm typecheck`、`pnpm lint`、`pnpm test` 全绿；新 Web 的切片另有 Playwright 用例；文档同步（README、AGENTS.md、本目录、设计系统）。

## M0 地基

| 切片 | 内容 | 验收 |
| --- | --- | --- |
| M0.1 设计基础 | tokens 单一来源 `packages/ui/src/tokens/haven.ts`；原型按 v2 信息架构重做；`.pen` 只保留关键页面，设计系统与组件单列 | 已在本分支完成 |
| M0.2 组件库 | 把原型里的组件（按钮、输入、Select、日期、菜单与右键菜单、抽屉、卡片、「?」…）做进 `packages/ui`，原型改为直接使用它 | 浅色 / 深色、键盘、触摸、减少动态效果；组件页能体验每个状态 |
| M0.3 新基线 | 按[数据模型](data-model.md)写 Drizzle schema，生成唯一的基线迁移；删除 v1 的 schema、迁移和种子；发现 v1 迁移记录时拒绝启动 | 空库一条命令建好；`db` 测试项目全绿 |
| M0.4 API v2 骨架 | `modules/*` 结构、统一错误与分页、contract、身份与成员；`/api/bootstrap` 返回 `api_version` | 按 [api.md](api.md) 核对；客户端版本不匹配时提示更新 |
| M0.5 Provider 层 | `packages/providers` 与 `apps/api/src/providers`：LLM、图像、搜索、存储、沙箱，以及新增的 STT、TTS、视频；消息渠道也用同一层 | 「测试连接」可用；业务代码不读 `process.env`；Key 只发往配置的地址 |
| M0.6 单引擎 | 对话与运行只用一个引擎；定时只属于 Agent；先做长任务探针，再删 Missions | 探针：电脑里 60 分钟以上的命令能断点续跑，容器重启后能恢复 |
| M0.7 删除 | 删除清单里的模块随替代切片一起删：代码、路由、工具、i18n、测试、文档 | 功能清单里对应行改为「已删」 |

## 风险

| 风险 | 应对 |
| --- | --- |
| #64 迟迟不合并 | v2 只在 #64 合并后开始；必要时把 #64 拆小合并 |
| 删除 Missions 后长任务能力下降 | M0.6 先做探针，结论不确定就推迟删除 |
| v2 发布前各端连不上 v2 服务器 | `v2` 分支不部署到生产；另开一个 v2 预览实例 |
| 现有部署要历史数据 | 留在 `release/v1`，等 M5；迁移指南先写好，避免 v2 的表结构做出搬不过来的决定 |
| 私有 overlay 依赖的扩展面变化 | 扩展面的变化在 EXTENDING.md 里列清单，M4.5 一次迁完 |
| 重写周期长 | 按切片交付；每个切片都能独立演示和验收 |
