## 维护约定

1. 先改文档，再改代码。新功能先在功能清单加一行，说明它属于哪个[对象](prd.md#4-对象模型)，以及为什么不能复用现有功能。
2. 同一个 PR 同步状态。功能落地后把清单里的状态改为「已实现」并写上 PR；删除一个功能时改为「已删」，同时清理导航、路由、工具、i18n、测试、种子数据、文档和截图。
3. 词汇只用[术语表](prd.md#5-术语表唯一词汇)里的。界面文案、代码命名、文档都一样。新词先进术语表。
4. 设计和事实分开。画板和原型能证明设计，不能证明功能已经上线。只有合并后的代码和通过的测试，才能把状态改为「已实现」。
5. 表结构变了就同步[数据模型](data-model.md)；会影响以后迁移的决定，同步[迁移指南](migration-v1.md)。
6. PRD 有变更记录。定位、对象、信息架构或范围变化时，更新 PRD 的版本号并在 §14 记一行。
