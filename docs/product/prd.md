## 0. 摘要

Greenhouse v1 的能力是够的，难用是因为重复：三套对话界面、四种创建 Agent 的入口、八种「任务」、六种分享方式、九个搜索框、四套评分。v2 的工作是减法和收敛：

- 一个定位：团队的 AI 同事，以及一起工作的地方。
- 十个对象：Agent、对话、运行、文档、表格、应用、技能、连接、服务、成员。每个对象只有一个家。
- 四个主入口：对话、知识库、表格、应用。另有运行、通知、我三个常驻入口。
- 一个引擎：所有对话和后台工作都跑在同一个 Agent 引擎上。
- 常驻：Agent 被消息和事件叫醒，在后台把事做完；要人决定的事按可逆性分级；崩溃或发布后从中断处继续。见[常驻 Agent](always-on.md)。
- 可插拔服务：模型、语音输入、语音输出、图像、视频、沙箱、搜索、存储、邮箱都是可选 Provider。可以用环境变量初始化，也可以运行时配置；管理员允许时，成员可以用自己的 Key。
- 安静的界面：每个区域只有一个主操作。非必要的说明收进浅色「?」。

## 1. 定位

一句话：Greenhouse 是开源、可自托管的团队 AI 同事平台。每个成员都有自己的 Agent；人和 Agent 在同一份知识、表格与应用上协作。外部服务全部可插拔，所有能力都通过 MCP 开放。

| 价值 | 含义 | 由谁兑现 |
| --- | --- | --- |
| 每个人都有 AI 同事 | Agent 有名字、职责、记忆和自己的电脑，在后台做事，只在需要时找你 | 对话、Agents、运行 |
| 一个工作底座 | 人和 Agent 读写同一份知识和数据，权限只有一套 | 知识库、表格、应用 |
| 开放、可替换 | 自托管；模型等服务随时更换；通过 MCP 进出 | 服务、连接、MCP |

Greenhouse 不是：
- 面向外部客户的客服机器人：没有访客或匿名登录，也没有公开链接。
- 通用低代码平台：应用只基于表格，不生成整套代码。
- 邮件客户端或 IM：每个 Agent 有自己的邮箱地址，来信进它的对话；邮箱和 IM 是 Agent 的工具与通知渠道，不提供收件箱界面。
- 组织架构同步工具：不做部门同步，分组由管理员维护。

## 2. 用户与场景

| 角色 | 是谁 | 关心 |
| --- | --- | --- |
| 成员 | 团队里的知识工作者 | 把事交出去、拿到可靠结果、该决定时被叫到 |
| 搭建者 | 愿意为别人搭表格、应用、Agent、技能的成员。这是一种行为，不是角色 | 搭得快，改了不出事，知道谁在用 |
| 管理员 | 部署和运维的人（角色 `admin`） | 服务配好、成员和预算可控、数据不外泄 |

核心任务：

1. 交办：在对话里把事说清楚，Agent 在前台或后台完成，需要时找我批准、登录或接管。
2. 找依据：在知识库找到可信内容，或让 Agent 带出处回答。
3. 跑流程：用表格组织事实，用应用让同事提交、审批、查看。
4. 看进展：在「运行」里看到所有后台工作的状态和产物。
5. 用自己的东西：连上自己的账号和工具，必要时用自己的模型 Key。

一个成员的一天：打开就是和主 Agent（默认叫 Greeny）的主线。对话侧栏的提示表示有 2 件事需要我：一个 Agent 要批准一次写入，另一个要我接管电脑完成验证。我在对话里把周报交给「周报 Agent」后台运行，在知识库里改一份制度，在「IT 工单」应用里处理一条申请。下班前打开「运行」，确认今晚的定时任务都已排好。

## 3. 产品原则

1. 一个对象，一个家。 每类对象只在一个地方创建和解释，其他地方只链接过去。
2. 结果先于过程。 先给结论和产物；工具步骤、推理、日志默认折叠。
3. 安静的界面。 每个区域只有一个主操作；页面不放架构解释，也不放装饰数字。补充说明收进浅色「?」，必要信息（错误、后果、权限原因）始终可见。
4. Agent 是同事。 人在界面上能做的，Agent 用同样的权限通过工具也能做；外部 Agent 通过 MCP 也能做。
5. 人做决定。 对外发送、不可撤销的操作和人机验证，永远由人确认。写入共享对象由人确认，或者在人预先授权的范围内执行。在自己范围内、可以撤销的写入直接执行，并留下回执。确认卡写明对象、影响和范围。见[常驻 Agent](always-on.md) §4.1。
6. 默认私密。 管理员不读成员对话；分享必须显式；发布 Agent 不暴露主人的私有数据。
7. 服务可插拔。 外部服务都走 Provider，不写死任何厂商；没配置的能力就不出现，不假装可用。
8. 跨端同一种语言。 Web、iOS、Android、浏览器扩展、桌面共用语义、术语和颜色，各自遵循平台习惯。

## 4. 对象模型

| 对象 | 定义 | 家 | 关键关系 |
| --- | --- | --- | --- |
| 成员 Member / 分组 Group | 人。角色只有 `admin` / `member`；分组是管理员维护的受众 | 管理 → 成员 | 分享、发布、应用受众都指向成员或分组 |
| Agent | AI 同事：身份、指令、技能、连接范围、记忆、电脑、邮箱、定时 | 对话目录顶部的 Agent 区 → Agent 资料 | 属于一个成员；可发布给受众 |
| 对话 Conversation | 人与 Agent 的消息流。四种：主线、Agent 对话、会话、房间 | 对话 | 包含消息、附件、富结果、「需要你」卡片 |
| 运行 Run | Agent 在后台做的一件事：步骤、状态、需要你、产物 | 运行 | 由对话、定时或表格自动化触发；属于一个 Agent |
| 文档 Doc / 文件 File | 知识库内容，放在文件夹里。文档以 Markdown 为准 | 知识库 | 团队 / 个人范围；可分享给成员或分组 |
| 表格 Base | 数据表、字段、记录、视图、表单、自动化 | 表格 | 应用基于它；「项目」是它的模板 |
| 应用 App | 基于一个表格的页面集合，带角色与受众 | 应用 | 发布版本；受众是成员或分组 |
| 技能 Skill | 可复用的做法：说明 + 可选文件 + 变量。模板是只有说明和变量的技能 | 技能 | 装备给 Agent；在输入框用 `/` 调用 |
| 连接 Connection | 成员接入的外部账号：MCP 连接器，以及内置连接器（个人邮箱）；IM 账号随 IM 渠道 | 设置 → 连接 | 连接器由管理员安装，连接由成员建立 |
| 服务 Provider | 一种能力的后端实现，例如某个模型服务商的 Key | 管理 → 服务（个人 Key 在 设置 → 我的服务） | 被对话、运行、工具按能力解析使用 |

通知不是独立对象。它是指向上面某个对象的「注意力」，打开就回到来源。

### 6.2 窄屏与移动

- 小于 768px 的 Web 与原生 App 结构一致。抽屉里依次是 Agent 区（主 Agent 在最上方）、房间、会话；底部是模块栏：对话、知识库、表格、应用、更多。页头左边是抽屉按钮，右边是通知。行高至少 44。
- 详情从底部 Sheet 打开；长表单和编辑器全屏。
- 768–1023px：全局栏常驻，目录以浮层打开。1024px 及以上：目录常驻。
- 平板（iPad 与 768px 以上的窗口）按上面两档排版，详情用右侧抽屉；可以改视图的筛选、排序和分组。
- 手机上搭建类页面只读：表结构与视图配置、应用搭建器、技能文件、管理里的服务。页头给「在电脑上继续」，不提供简化的编辑器。Agent 在手机上可以从模板新建，可以改名字和头像、暂停定时、撤销预先授权；长指令在电脑上写。
- 在卡片上做完决定后，提示还有几件需要你，并可以直接跳到下一件所在的对话。这只是跳转，决定仍在来源对话里做。

## 7. 模块需求

每个模块分四部分：目标、要有、v2 改变、不做。逐项的功能 ID 与状态见[功能清单](features.md)。

### 7.1 对话

目标：在一个地方和 Agent、同事说事，拿到结果，并在需要时做决定。

要有
- 四种对话：主线、Agent 对话、会话、房间。它们共用一套消息、输入框和侧栏。
- 输入框：
  - 文本、附件（任意文件，图片内联）、引用回复片段。
  - `@`：房间里点名某个成员或 Agent；新会话里切换 Agent。
  - `/`：调用技能，带变量时先填第一个字段。
  - 语音输入（STT；未配置服务时隐藏）。
  - 发送与停止互斥。生成中可以继续发，消息会排队。
- 回复约定：简单事实、日常操作与完成确认用 1–3 句纯文本。聊天不写标题，不用加粗强调；名字、版本、数字和链接不包行内代码。代码、三个以上并列项和确有必要的表格才用 Markdown，链接用标题。成员回合流式写同一条回复，工具前言清除；唤醒正文为私有草稿，只有 `send_message` 发布有用更新，无事保持静默。
- 消息：
  - 作者、时间；房间里显示已读（悬停或点按查看）。
  - 操作：复制、👍 / 👎、朗读（TTS；未配置时隐藏）、从这里新开会话。
  - 只能编辑或重新生成自己的最后一条。
- 结果先于过程：
  - 结论和富结果直接显示：表格、图表、指标、卡片、步骤、Mermaid、网页预览、图片、视频、音频、文件。
  - 工具步骤合成一行摘要，推理默认隐藏。
- 回复里的卡片只有一种布局，分三类：结果（记录、表格、图表、文件、媒体）、过程（工具调用、多步运行）、决定（「需要你」）。
  - 标题行：图标、标题、一段简短元信息，状态标签固定在最右侧。
  - 过程卡片折叠成一行，以箭头开头；完成态用中性色，只有运行中、失败、需要你着色。
  - 决定卡片的按钮在右下；结果卡片的操作（打开、下载、预览）在左下。
- 「需要你」卡片，共五种：批准、登录、接管电脑 / 人机验证、提问（表单）、提议（新建 Agent、修改指令、开始后台运行）。
  - 待处理时标签是「需要你」。卡片写明对象、影响和范围；终态不可再点。同主题同目标的新请求取代旧卡并链接新卡；取消回合或运行撤回卡片；聊天回答收敛问题。请求终态清理所有客户端的通知，历史留在对话。
- 一个侧栏，一次只开一项：信息（成员、摘要、共享笔记）、电脑、预览（记录 / 文档 / 文件 / 网页）。
- 组织方式：置顶、归档、目录内搜索。超长对话自动摘要，不截断。
- 页面助手：在任何页面按 `⌘J` 打开同一个对话组件，自动带上页面上下文；它保存为一个会话。

v2 改变
- 只保留一个对话引擎（原 Agents 引擎）。删除旧 Chat 引擎、`ConversationPane` 和旧助手浮层引擎。浏览器扩展和 IM 机器人以后也接同一引擎（v2.0 之后）。
- 「Chat」和「Message」两个入口合并：Agent 资料里只有「发消息」（打开 Agent 对话）。新会话从「新会话」开始。
- 删除会话标签、文件夹、历史弹窗、会话评分与管理员评语、会话分享链接与「分享给我」、消息翻译、单条导出 PDF、消息全屏、团队范围（管理员读成员对话）。
- 工作台（新会话空状态里的卡片、配方、拖拽网格）删除。新会话的空状态只显示问候、输入框，以及 3 个常用技能。

不做：对外公开分享对话；管理员读取成员对话；在锁屏上直接批准（通知上的批准要先解锁，第 3 档只在来源对话里批，见[常驻 Agent](always-on.md) §4.1）。

### 7.2 Agents

目标：每个成员拥有职责清楚、权限可控、会记事的 AI 同事。

要有
- 三类 Agent：
  - 主 Agent：每人一个，不能归档或发布。
  - 私有 Agent。
  - 公开 Agent：发布固定版本给成员或分组，有独立预算；主人能看用量和评价，看不到对话内容。
- 私有 Agent 也可在对话中由 `agent_mutation` 直接创建／修改，留可撤销回执；发布和分享由成员亲自操作。当前 Agent 修改自己的指令仍用 `self` 提议，接受后生效。
- 创建入口只有一个：「新建 Agent」，可以选模板，也可以从空白开始。主 Agent 提议新建时，打开的是同一张表单（已预填）。
- Agent 资料只有一个家（`#/agents/:id`，也可以从对话页头以抽屉打开）。分页：
  - 资料：名字、植物头像、职责、指令。
  - 能力：技能、可用连接器、权限（只读 / 可写）、预先授权（可以撤销），工具明细放在「高级」。
  - 记忆：查看、修改、忘记。
  - 定时。
  - 电脑。
  - 发布：仅公开 Agent。
  - 用量与活动。
- 电脑：每个 Agent 一台，由沙箱服务提供。
  - 能观看、接管、全屏、用终端、管理文件和进程；满额开机排队，停机前加密备份主目录，管理员可备份及恢复。
  - 遇到人机验证时交给人，由人交还。
  - 登录凭据来自密码库，Agent 用得到但看不到明文。
  - 沙箱服务未配置时，所有电脑入口都不出现。
- Agent 之间可以转交工作，也可以在房间里协作。转交会带上发起人的权限，并有深度、次数和循环限制。
- 指令修改通过「提议」卡片，由人确认。

v2 改变
- 四种创建入口合并为一个。「设置 → 我的 Agents」和「浏览 Agents」弹窗合并进 Agent 目录。
- 个人「记忆」设置页删除：记忆归各个 Agent 管理；所有 Agent 都应知道的事写在「设置 → 账号 → 关于我」。
- 「最大步数」等技术参数从界面移除，改为系统默认值。
- 模型：管理员配置了多个模型时才出现选择，默认用工作区的默认模型。

不做：Agent 定义的分享、克隆与审核流程（v1 已删除，不恢复）；Agent 群聊（已退役，v2 删除残留）。

### 7.3 运行

目标：一处看到所有后台工作的事实，需要时作决定，结束后拿到结果。

要有
- 列表分三段：运行中、定时、已结束；可以按 Agent 和来源（对话 / 定时 / 表格自动化）过滤。
- 运行详情：状态、步骤、需要你、产物、来源对话、取消、重试。重试只重跑失败的步骤。
- 定时：在 Agent 资料的「定时」页创建（也可以在对话里让 Agent 创建）。运行页列出全部定时，可以暂停、立即运行或删除。服务停机期间错过的多次触发，恢复后只补跑一次。
- 长时间、需要文件与命令行的工作，在 Agent 的电脑（沙箱）里完成。
- 后台运行能读记忆和来源对话，能用连接器的只读工具，也能用电脑（要在简报里声明，出网只放行声明的域名）。写入按审批分级处理：
  - 自己范围内的直接执行；
  - 共享的发卡片，或按预先授权执行；
  - 对外的永远发卡片。
  - 发卡片后运行等待，批准后接着做。
- 唤醒：除了人的消息，以下事件也能叫醒 Agent：
  - 运行结束后的跟进；
  - 电脑里的进程结束；
  - 主人在知识库里 `@` 自己的 Agent；
  - 表格自动化。
  - 同一来源的事件去重，2 分钟内的合成一个回合；事件链深度和每天叫醒的次数有上限。
- 崩溃或发布后，从中断的步骤继续。有副作用、结果不确定的步骤不自动重做，标为「结果未知」。
- 定时可以设「没有发现时不通知」；失败总是通知。

v2 改变
- 只用一个运行引擎：在 v1 Runtime kernel 的基础上收敛。
- 删除 Missions：一次性沙箱、Pi 运行器、`agent-runner` 镜像、Mission 卡片与详情页、`/api/missions`。它的场景改由「后台运行 + Agent 电脑」承接。
- 删除 Workflows：DAG 引擎、`workflow_plan`、节点编辑器与人工关卡。多步协作由 Agent 转交和后台运行完成。以后有真实需求，再以「流程」重新设计。
- 删除独立的 Automations 页面。定时只属于 Agent。
- 删除运行类型分类（Mission / Workflow / Automation / Subagent）和「复制为评测用例」。

不做：多级审批；面向开发者的 DAG 编排界面。

### 7.4 知识库

目标：团队可引用的依据，有出处、有版本、权限清楚。

要有
- 文档与文件放在同一棵文件夹树里。文档用富文本编辑，以 Markdown 存储。文件可以上传、预览、下载。
- 范围：团队、个人、分享给我。分享对象是成员或分组，分读和写两种权限。
- 编辑器：`/` 块、`[[` 引用文档、`@` 提及、图片、表格、模板、「他人正在编辑」提示、未保存保护。
- 版本历史（对比、恢复）、评论、反向链接、归档 / 恢复、导出（Markdown 压缩包）。
- 搜索：中英文全文检索。Agent 回答时带出处。
- 每个 Agent 有一个私有参考文件夹。

v2 改变
- 文件柜（Drive）并入文件夹树，不再有单独的附件页。
- 删除知识库的 AI 生成、改写、补全接口（没有界面；改为在对话里让 Agent 做）。
- 「常见问题 / 相关话题」面板不再显示，字段只作为检索元数据保留。
- 知识库和技能的通知统一走通知中心，删除单独的企微 / 飞书 webhook 推送。

不做：公开 Wiki；多人实时协同编辑（保留「他人正在编辑」提示）。

### 7.5 表格

目标：组织共享事实，让人和 Agent 读写同一份结构。

要有（以 PR #64 的「表格 → 应用」阶段 0–2 为基础）
- 层级固定为：表格 → 数据表 → 视图。
- 字段类型：文本、长文本、数字、勾选、日期、单选、多选、成员、链接、附件、关联、公式、汇总、AI 字段。
- 视图：表格、看板、日历、画册，以及新增的时间线（甘特）。视图都支持筛选、排序和分组，可以保存为个人或共享视图。
- 记录：
  - 在详情里直接编辑：桌面是抽屉，手机是底部 Sheet。
  - 评论、活动、回收站。
  - 批量粘贴，CSV 导入和导出。
- 新增「父记录」与「依赖」字段，用于子任务和时间线箭头。
- 表单：仅限内部提交，可附文件。
- 自动化：记录创建、限定字段的更新、开始符合条件、时间间隔、日期到达或按钮触发；通知成员、发送签名的公网 HTTPS webhook，或执行 Agent 步骤（默认无工具，可明确授予源表格只读；结果写入仍走审批分档）。
- 权限：拥有者、搭建者、编辑者、查看者四种角色，加行级和列级权限，可以分享给分组。
- 「项目」模板：项目、任务、里程碑、负责人、日期、依赖。
- 任何记录都可以「交给 Agent」：生成一次运行，负责人仍然是人。
- Agent 可以在对话里规划表结构，由人确认后生效。

v2 改变
- 项目模块并入表格。 v1 的项目、任务、甘特、看板改由「项目」模板和时间线视图承接。删除 `/api/projects`、项目页面、项目工具，以及移动端的项目模块。
- 表格自己的通知收件箱删除，统一进通知中心（#64 D10）。
- 仪表盘作为表格内的一种视图保留；应用页面复用同一套图表卡片。

不做：公开表单；与外部数据库双向同步；部门同步。

### 7.6 应用

目标：把表格变成同事真正会用的界面，按人和分组发放。

要有（PR #64 阶段 1–2）
- 应用中心：我的、分享给我、置顶、精选（管理员推荐）。
- 运行时页面：卡片有列表、表格、看板、表单、图表、指标和动作。动作需要审批时走「需要你」。
- 搭建器：
  - 页面、画布、角色、受众、按角色预览。
  - 发布时显示差异和权限变化。
  - 版本历史。
- 模板：管理员审核后可用。
- Agent 可以通过 `apps_query` / `apps_action` 读写应用，结构变化需要人确认。

v2 改变：作为一级入口进入全局栏（#64 设计稿里没有，这是 V2 设计的主要缺口）。

不做：公开链接；整套代码生成。#70：自定义 HTML／JS 卡片由搭建者编写，每个不可变发布版本须经管理员按 hash 审核后才运行。未审核显示占位，不发送源码。只能绑定本应用的表格只读数据卡；不能绑定连接器或写数据。外部数据卡另走查看者自己的连接，仅显示声明式映射后的纯数据。

### 7.7 技能

目标：把成熟做法沉淀下来，人和 Agent 都能复用。

要有
- 技能库，分团队和个人。技能可以是 SKILL.md 包（说明 + 文件 + 脚本），也可以是只有说明和变量的模板。
- 版本不可变，带变更说明和 sha256；有安全扫描和审核；可以下载 ZIP、上传新版本。
- 可以装备给 Agent；在输入框用 `/` 调用；可以把一段对话「存为技能」。
- 每个技能写明运行要求，例如需要电脑或某个连接器。条件不满足时禁用，并说明原因。

v2 改变
- Prompt Tasks（「我的任务」）合并进技能，删除 `/api/prompts`、Tasks 页面和 `task_capture` 卡片。
- 改名：SkillHub → 技能。入口在「更多」和 Agent 资料的「能力」页。
- 删除通过 `/技能` 启动 Mission。技能在对话里执行，或者作为后台运行执行。

### 7.8 通知与搜索

通知
- 一个通知列表；审批在来源对话处理，对话侧栏标记待处理请求并按设置推送。
- 所有来源统一调用 `publishNotification`：对话、运行、表格、应用、知识库评论与 @、技能扫描、分享。
- 送达渠道：站内、邮件、手机推送，由成员在设置里选择；推送预览默认关闭。IM 渠道在 v2.0 之后加入。
- 只有一个角标，在铃上。
- 回复与提及：被 `@` 时立即通知；Agent 的回复只在离开一分钟仍未读时通知；读到哪里，通知就读到哪里。
- 不做免打扰时段：交给系统的专注模式，以及飞书、企微的免打扰。

搜索
- `⌘K`：全局搜索加命令，覆盖对话、文档、记录、应用、Agent、技能，以及「新建…」「打开…」。
- 模块目录里的搜索只筛选当前列表。
- 删除历史弹窗，也删除 v1 里重复的约 9 个搜索框。

### 7.9 设置、管理、登录

- 设置与管理的分区见 6.3；页面模式统一，见 [设计系统 · 模式](../design-system/patterns.md)。
- 保存语义：
  - 开关和偏好即时保存。
  - 一组配置用一次显式保存。
  - 机密只写不读。
  - 同一区块不混用即时保存和显式保存。
- 登录：邮箱 + 密码。首个管理员通过启动邀请链接激活；成员由邀请激活；重置密码通过一次性链接。配置了邮箱服务时，邀请和重置自动发邮件，链接仍可复制。飞书等扫码登录随 IM 渠道，在 v2.0 之后。
- 登录页只有标志、「Greenhouse」、邮箱、密码和一个大号登录按钮（高 44）。不放说明文字。
- 删除：
  - 管理页：Feature Requests、Frictions、Evaluation（网页、API、数据集、评审 Profile）、AI Gateway 与 LLM 中继（`/api/llm`、中继 Key）、在线用户弹窗、未使用的自定义角色接口。
  - 品牌工作室的高级 token 编辑（字体、圆角、缩放、语义色覆盖），只保留名称、Logo、主色。
  - 个人「分组」设置页：分组改为管理员维护。

## 8. 平台能力

### 8.1 服务（Provider）

9 类能力都可以替换为任意 Provider。详见 [providers.md](providers.md)。手机推送和以后的 IM 渠道也按同一套 Provider 配置。

| 能力 | 用在哪里 | 未配置时 |
| --- | --- | --- |
| 大模型 LLM | 所有对话、运行、标题、摘要、记忆整理 | 系统不可用，初次启动引导管理员配置 |
| 语音输入 STT | 输入框麦克风；音频附件转写 | 用浏览器自带识别；不支持的浏览器隐藏麦克风 |
| 语音输出 TTS | 消息「朗读」；Agent 生成音频 | 用浏览器自带朗读；不支持则隐藏 |
| 图像 Image | `generate_image`，以及编辑参考图 | 工具不提供，界面不提及 |
| 视频 Video | `generate_video`（异步） | 同上 |
| 沙箱 Sandbox | Agent 电脑、长时间运行 | 电脑相关入口全部隐藏 |
| 搜索 Search | `web_search` / `web_fetch` | 工具不提供 |
| 存储 Storage | 所有文件：上传、附件、产物、导出、技能包、电脑备份 | 本地磁盘 |
| 邮箱 Mail | 系统发信（邀请、重置密码、通知邮件）；Agent 邮箱的收信与发信 | 不发邮件，邀请与重置改为复制链接；Agent 没有邮箱 |

配置来源的优先级：
1. 成员自己的 Key，前提是管理员允许。
2. 工作区运行时配置（数据库）。
3. 环境变量初始化。
4. 内置默认。

改动立即生效，不需要重启。

### 8.2 权限与隐私

- 角色只有管理员和成员。每个成员可以按模块开关（知识库 / 表格 / 应用 / 电脑），并有月度预算。
- 一条规则：Agent 的能力 = 授权范围 ∩ 负责人此刻的权限。
- 管理员不读成员对话、私有 Agent 记忆和密码库，也没有对应开关（删除 `SUPER_READS_CHATS`）。
- 删除按成员的功能开关（`user_features` 的 memory / tables / cloud-agent / bots），改为模块权限加服务可用性。

### 8.3 开放与扩展

- MCP 服务器（`/api/mcp`，OAuth 2.1）是对外的唯一接口。删除 `/api/agent` 工具代理，CLI 改走 MCP。
- MCP 客户端（连接器）：管理员安装，成员连接自己的账号，Agent 通过 `mcp_call` 使用；写操作需要确认。
- 扩展（`greenhouse.config.ts`）：可以贡献页面、设置和管理分区、实体详情、搜索来源、工具，以及 Provider 适配器（新增）。删除工作台配方这个扩展面。

### 8.4 渠道

- 邮件：系统发信与 Agent 邮箱都走邮箱服务（§8.1），用云邮件服务的收发能力；SMTP 只能发信。
  - 每个 Agent 一个专属地址。来信进它的 Agent 对话；发件人在名单里才叫醒它（默认是主人和工作区成员），其余来信留存，主人可以放行。
  - Agent 发信、回信永远由人批准。
- 个人邮箱：经内置连接器（IMAP / SMTP）连接，供 Agent 读信、起草和发送（发送需确认）。
- 手机推送（Expo / APNs）：v2.0 先做。
- IM 渠道：飞书、企微、Slack、Discord、Telegram 统一设计（账号绑定、机器人、消息送达、扫码登录），在 v2.0 之后。飞书、企微的送达代码已有，随 IM 渠道一起开放。
- 推送配置放在「管理 → 服务」，同样支持环境变量初始化和运行时修改。删除共享团队邮箱。

### 8.5 多端

| 端 | 范围 |
| --- | --- |
| Web | 全部功能，v2 重写 |
| iOS | 对话、Agents、电脑、知识库、表格与应用（#64）、通知推送、小组件、实时活动；v2.0 与 Web 一起打磨 |
| Android | 对话、Agents、知识库、表格与应用、通知推送；v2.0 与 Web 一起打磨 |
| 浏览器扩展（v2.0 之后） | 侧栏对话（带页面上下文）、保存网页到知识库、受控浏览器操作 |
| 桌面 App（v2.0 之后） | 承载 Web；快捷启动、划词、截图、托盘 |

v2 API 不兼容 v1 客户端：移动端与服务端 v2 同时发布；扩展和桌面在 v2.0 之后跟上。服务端在 `/api/bootstrap` 返回 `api_version`，客户端发现不匹配时提示更新，不白屏。

### 8.6 数据

- v2 从零建表：迁移链从 v2 基线开始、之后增量追加，不继承 v1 的迁移链，也不在 v1 库上原地升级。表结构见[数据模型](data-model.md)。
- v2 启动时发现库里有 v1 的迁移记录就拒绝启动。
- v1 的历史数据迁移推迟到 v2 稳定之后，以离线 ETL 进行，见 [v1 数据迁移](migration-v1.md)。v2.0 只提供这份指南，不提供迁移工具。

## 12. 成功指标

| 指标 | 定义 | v2 目标 |
| --- | --- | --- |
| 北极星 | 每周每个活跃成员被采纳的 Agent 产出数（👍、确认的写入、下载或引用的产物） | 比 v1 基线提升 |
| 激活 | 新成员首日完成一次「交办并采纳」的比例 | ≥ 60% |
| 决策时延 | 「需要你」从出现到处理的中位时间 | < 30 分钟（工作时间） |
| 运行成功率 | 后台运行成功结束的比例 | ≥ 90% |
| 打扰成本 | 每个活跃成员每天的「需要你」卡片数（中位数）、批准率、对外或不可逆操作的占比 | 卡片数 ≤ 10，批准率 < 95%；超出时评估审查模型 |
| 缓存命中率 | 长对话和后台运行的输入 token 中，命中提示缓存的比例 | 同一对话第二轮起大于 0，逐版本提升 |
| 界面简洁度（自检） | 一级入口 ≤ 7；设置分区 ≤ 7；管理分区 ≤ 7；每页主操作 = 1 | 发布前满足 |

v1 没有采集使用量，这些指标的埋点作为 M3 的一部分落地，只记录计数，不记录内容。
