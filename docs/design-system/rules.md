# 交互规则

更新 2026-10-16。每一条都是做界面时必须守的规则；细节、取值和例外见各专题文件。Web 与原生都适用，原生按平台习惯实现。

## 对话

- 一对一对话不显示 Agent 的头像和名字。房间里头像和名字在消息上方一行，正文占满宽度，不留头像列。
- 进行中只给轻提示：当前步骤的文字和动态点，不多出一行头像。
- 回复默认纯文本，简单问题 1–3 句。格式只用于代码、三项以上的并列和表格；不用粗体强调，名字、版本、数字、网址不用行内代码，不加标题。
- 「好的」「收到」用表情回应，不单独回一条。
- 被事件叫醒时，没有值得告诉成员的就不发消息。
- 消息操作收进「⋯」：Web 悬停时出现，触屏上常驻但弱化；点开是菜单。

## 需要你

- 只有一个字段、不超过 6 个选项的单选，直接在消息里点选。多选、输入和多个字段用抽屉或 Sheet。
- 卡片按钮放左下，主按钮在前。危险操作用红色，按钮上写明对象。
- 卡片只显示对决定有用的内容：对象名称、位置、会发生什么变化。不显示编号、内部字段名、默认值和一串「否」。
- 时间写成人话，比如「每天 08:00」，不显示 cron。
- 处理过、过期、被取代、撤回的卡收成一行，相关通知同时消失。同一 Agent 对同一对象的新请求取代旧的。
- 没有单独的「需要你」中心：待处理的卡在对话里，侧栏对话上有角标，同时推送。

## 回执与过程

- 回执写动词和对象名，比如「新建了 Agent「晨间邮件」」。同一回合对同一对象的写入合成一张回执，一个撤销。
- 步骤标签写人话，不出现工具名。失败写原因：网站拒绝访问、超时、没有权限、内容太长。
- 整轮成功时，中途失败的步骤只作中性提示，不显示红色「失败」。只有最终没有完成才标失败。

## 抽屉与 Sheet

- 只有一种结构：顶部标题和关闭，中间正文可滚动，底部操作栏固定。Web 主操作在操作栏右侧；原生主按钮满宽，在最底部。
- 打开时遮罩盖住全部背景，包括左侧栏和导航栏。
- 有未保存的内容时，关闭前要确认。
- 不嵌套卡片，不重复标题。

## 组件

- 分段控件用于同一内容的不同视图，最多 4 个短选项。标签页用于页面内的不同部分。两者高度、圆角、字体、指示条和焦点同一套。
- 按钮、输入框、选择器、徽章、菜单、列表行、空状态、提示条各只有一套变体，取值全部来自 tokens，不写一次性的样式。
- 加载用骨架，保持最终布局的形状。超过 1 秒的等待写明正在做什么。

## 主题与对比

- 浅色靠层次区分：画布略带灰，卡片、输入框、抽屉、菜单是纯白。深色靠明度分层。
- 正文对背景 ≥ 7:1，次要文字 ≥ 4.5:1，分隔线对画布 ≥ 1.45:1，选中和悬停在两种主题里都要看得出。

## 动效

- 动效只用来说明变化：出现、状态切换、展开收起、开合、指示条移动、列表插入和删除。
- 时长 120–240 ms，取值来自 motion tokens。系统开启「减少动态效果」时只保留淡入淡出。
- 不做装饰性的循环动画，不做粒子。

## 文案

- 中文和英文、数字之间加空格，中文之间不加，比如「Greeny 的电脑」「发布助手的电脑」。
- 界面上不出现内部编号、枚举值、工具名和英文字段名。
- 错误写清原因和下一步，不写「服务未能完成这次操作」这种空话。
