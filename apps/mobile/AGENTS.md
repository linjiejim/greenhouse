# 移动端（@greenhouse/mobile）

Expo SDK 57 / React Native 0.86 / React 19.2 的**原生 App：iOS 走系统组件（SwiftUI / UIKit / Liquid Glass），Android 走 Material 3（Jetpack Compose）**（2026-10 原生化重写，spec：`docs/specs/20261005-mobile-native-ios.md`；最早从 letpot-greenhouse 的 apps/mobile 搬迁而来）。功能：**对话（AI-first，抽屉里的流式 Agent 聊天 + 图片上传 + 会话标签 / 分享 / 重命名 / 置顶）· 知识库（浏览 + 搜索 + 作用域筛选 + 原生编辑 + 修改历史/恢复）· 项目管理（列表/看板/甘特 + 任务树/评论/成员/动态）· 设置（主题/语言/标签/我的 Bot/连接器/工作站/账号）**。视觉 = **iOS 系统语义色 + Greenhouse Haven 强调色**（跟随系统深浅色，iOS 26 Liquid Glass）。Android 是 Material 3 版（Compose 表单 / 对话框 / 菜单、M3 调色板，见下文「Android 规范」），与 iOS 共用数据层与行为 hook。

## 原生 UI 规范（iOS 优先，所有新代码必须遵守）

目标：**像系统 App 一样原生**——能用系统组件的地方一律用系统组件，iOS 26 的 Liquid Glass / 菜单 / sheet / 表单 / 手势全部由系统渲染。UI kit 在 [src/ui/](./src/ui)，**直接按模块导入**（`../src/ui/list`），没有 barrel。

- **系统组件优先，禁止 JS 自绘替代品**：导航栏 / 返回 / 工具栏按钮 / sheet / 菜单 / 弹窗 / 表单 / 选择器 / 日期 / 开关 / 分段控件 / 搜索栏全部原生——`expo-router` 原生 Stack（react-native-screens）+ `@expo/ui/swift-ui`（真 SwiftUI）。**不要**再写自绘 header、JS bottom sheet（gorhom 已移除）、JS action sheet、JS 日历、自绘 Switch。
- **分层与 Liquid Glass**：控件层（导航栏、工具栏、浮动按钮、composer）= 玻璃；内容层（消息、列表行、卡片）= 实体系统色，**不上玻璃**。系统 chrome 自带玻璃；自定义浮动控件用 [src/ui/glass.tsx](./src/ui/glass.tsx)（`Glass` / `GlassGroup` / `GlassIconButton`，`LIQUID_GLASS` 判断可用性）——相邻玻璃放进 `GlassGroup`，不要玻璃叠玻璃。iOS<26 / Android 自动退化为实体面。
- **颜色 = iOS 系统语义色 + Haven 深林绿强调色**（[src/theme.ts](./src/theme.ts)）：`colors.*` 在 iOS 上是 `PlatformColor`/`DynamicColorIOS`（跟随深浅色、增强对比度、系统版本），是不透明对象——**不要拼字符串或做透明度运算**；需要真实色串（react-native-svg、导航 options、SwiftUI modifier、alpha 计算）用 `hex.*` 镜像，透明度一律 `alpha(color, a)`（支持 `#RGB`/`#RRGGBB`/`#RRGGBBAA`/`rgba()`）。表面用 `background`/`groupedBackground`/`secondaryGroupedBackground`，文字用 `label`/`secondaryLabel`/`tertiaryLabel`，分隔线 `separator`，填充 `fill` 系列，状态用 `red`/`orange`/`green`/`blue`（+`*Fill`），品牌/交互用 `accent`（`accentFill` 着色底、`accentText` 着色文字、`onAccent` 实心强调色上的字/图标）；**非强调色**实心底（系统色图标块、灰头像、项目色）上的字/图标用 `onTint`（白）。dark 模式的 accent 是浅绿色，上面放白字对比度不足——一律 `onAccent`。**不写 hex 字面量**（数据驱动的颜色如 tag 色板、项目色除外）。主题偏好由 `useApplyAppearance()` 经 `Appearance.setColorScheme` 覆盖整个 UIKit 外观。样式：模块级 `const useStyles = makeStyles((c) => ({…}))` + 组件内 `const { colors: c } = useTheme(); const styles = useStyles(c);`。
- **字体 = Nunito + 原生 text styles**：`typo.largeTitle/title1/title2/title3/headline/body/callout/subheadline/footnote/caption1/caption2`（正文 17pt），只用 `weight.*` 做强调；不要自造字号；不要关 `allowFontScaling`（动态字体）。Nunito 400/500/600/700 来自 `assets/fonts/`，由 expo-font 插件打包；RN 用 `typo`，SwiftUI 文字用 `brand-font.ts` 的 `brandFont`（保留 textStyle），Compose 文字用 `brand-text.android.tsx`。导航标题也用 Nunito；系统键盘/原生系统菜单保持 OS 字体，代码保持等宽。
- **图标 = SF Symbols**：`<Icon name="…" />`（[src/ui/core.tsx](./src/ui/core.tsx)，expo-symbols；Android 自动用对应 Material Symbol）。新增图标在 `ICONS` 表里登记 `[SF 名, Material 名]` 两个平台，只登记在用的，然后跑 `python3 scripts/android-icons.py`（生成 Android 矢量图）；导航栏按钮 / 菜单项的 `icon=` 一律 `toolbarIcon(name)`（[src/ui/toolbar-icon.ts](./src/ui/toolbar-icon.ts)：iOS 给 SF 名，Android 给图片源——Android 工具栏不认 SF 名，写死 SF 名在 Android 上什么都不画）。**`Icon` 默认对 VoiceOver 隐藏**（装饰性——否则 "gearshape.fill, 设置" 这类 SF 名会粘进每个行的朗读）；只有独立表意、旁边没有文字的图标才传 `accessibilityLabel`。lucide 已移除。
- **形状**：圆角一律配 `squircle`（`borderCurve: 'continuous'`），半径取 `radius.*`（`group` 26 = iOS 26 分组列表，`bubble` 20）。最小点击区 `HIT`=44。
- **导航地图 & 呈现方式**集中在 [app/_layout.tsx](./app/_layout.tsx)，用 [src/ui/nav.ts](./src/ui/nav.ts) 预设：`pageScreen`（大标题可折叠、内容滚到玻璃栏下的柔和边缘效果）/ `detailScreen`（行内小标题）/ `sheetScreen(detents, {header})`（form sheet）/ `modalScreen`（page sheet，带自己的 Stack）。**呈现方式只在 layout 声明**；标题与按钮由页面自己声明：`<Stack.Screen options={{ title }} />` + `<Stack.Toolbar placement="left|right">`（`Button` / `Menu` / `MenuAction` / `Spacer`）。返回按钮永远是系统的。新增路由要同步 spec 的路由契约表。
  - 每个纯图标工具栏按钮**必须**有 `accessibilityLabel`（否则 VoiceOver 读 SF 名，如 "drag"）。
  - 确认类主按钮：`<Stack.Toolbar.Button icon={toolbarIcon('check')} variant="done" tintColor={hex.accent} accessibilityLabel={t('common.done')} />`（不传 tintColor 会是系统蓝）。溢出菜单与动作并列时用 `overflowLast(menu, ...actions)` 排序（iOS `…` 在前、Android `⋮` 在最后）。
  - **sheet / modal 的 chrome 用共享件**（[src/ui/sheet-chrome.tsx](./src/ui/sheet-chrome.tsx)）：只读 sheet 的 ✕ = `<SheetClose />`；新建/编辑表单 = `<FormChrome title dirty canSave saving onSave />`（✕ 有未保存修改先确认放弃、✓ accent done 按钮、脏状态禁下滑关闭）；从 sheet 去完整页面 = `useLeaveSheetTo()(href)`（先关 sheet 再 push，直接 push 会把页面压进 sheet 的呈现上下文）。不要每屏复制这些块。
- **Sheet = 路由**（UISheetPresentationController）：详情预览 / 选择器 / 短表单都做成 `app/peek/*`、`app/sheets/*`（或模块自己的 sheet 路由，如 `projects/task-form`）路由，`sheetScreen([0.6, 1], { header: true })` 得到原生 grabber + 档位 + iOS 26 玻璃 + sheet 内原生导航栏；内容用 `ScrollView contentInsetAdjustmentBehavior="automatic"`。半高档的 sheet 是悬浮的，圆角底边下面露出后面的页面（通常是转录文字），被底边切开的一行会和后面的字读成一行——根 Stack 的 `screenLayout`（[src/ui/sheet-edge.tsx](./src/ui/sheet-edge.tsx) `sheetEdgeLayout`）给每个半高档的 form sheet 自动加一道淡出到玻璃的底边（`sheetDetentChange` 跟踪档位，全高时不加；sheet 自己别再画），所以半高 sheet 底部**不要钉按钮**。几个选项必须一眼都看到的 sheet（如「新建 Bot」）直接 `sheetScreen([1])`。传参：可 URL 化的走路由参数，结构化大对象走 [src/lib/handoff.ts](./src/lib/handoff.ts)（`putHandoff` → `?k=`，接收方必须处理 key 已失效的空状态）；**结果回传走 zustand store**，不要回调。web 的「详情抽屉 / entity peek」在移动端 = 底部 sheet 预览，再提供「打开完整页面」。
- **菜单 = 系统菜单**：[src/ui/menu.tsx](./src/ui/menu.tsx) `NativeMenu`——`trigger="tap"`（溢出 `…`、composer `+`、选择器 chip）/ `trigger="longPress"`（消息气泡、列表行、任务卡片的上下文菜单，带系统抬起预览）；`menuSections([[…],[删除]])` 分组，`checked` 打勾，`destructive` 红色，`children` 子菜单。导航栏里的菜单用 `Stack.Toolbar.Menu`。**没有 JS ActionSheet 了。** `items` 尽量 `useMemo`（`useT()` 返回的 `t` 是稳定的，可放进依赖）。触发器宽度已知时（抽屉行 = `DRAWER_W − 2×space.sm`、整宽行 = 窗口宽 / 列表 onLayout 宽）传 `width`，跳过量宽、子树只挂载一次；只有宽度随文本变化的（用户气泡）才用默认的量宽（量出的宽**向上取整**再钉——向下取整差零点几 pt，一行的气泡会把最后一个字挤到第二行）。长回复的上下文菜单用 [src/chat/message-menu.tsx](./src/chat/message-menu.tsx)（SwiftUI ContextMenu + 有界纯文本摘要预览）——community MenuView 总是抬起整个触发器，长内容会缩成一条。
- **对话框与反馈**（[src/ui/dialogs.tsx](./src/ui/dialogs.tsx)，系统 UIAlertController；Android 为 Material 对话框，见下文）：`confirmAction()`（删除/放弃/退出用 `destructive`）、`promptText()`（重命名/新建）。**反馈只有一条规则**：用户发起的操作失败（保存/删除/创建/恢复/重命名/发送/加成员/改状态——包括已回滚的乐观更新）→ `alertError(title, message?, detail?)`（系统 alert，单个「好」；服务商原始回答这类技术原文放 `detail`——收在「详情」按钮后面，不进 message）；限额/规则说明（标签上限等）也走 `alertError`；**`toast(msg, icon)` 只用于成功确认**（[src/ui/toast.tsx](./src/ui/toast.tsx)，玻璃 HUD，`ToastHost` 挂在根布局，在 iOS 上渲染进 `FullWindowOverlay`，从 sheet / modal 里弹也在最上层，VoiceOver 会播报）；页面加载失败 → 屏内 `EmptyState` + 重试。
- **表单 = SwiftUI**：设置 / 编辑 / 新建页一律 [src/ui/native-form.tsx](./src/ui/native-form.tsx) `NativeForm` + `@expo/ui/swift-ui` 控件（`Section`、`TextField`、`SecureField`、`Toggle`、`Picker`、`DatePicker`、`LabeledContent`、`Button role="destructive"`…）；键盘、聚焦、AutoFill、VoiceOver 全原生。色板（tag / 项目色）用同文件的 `ColorSwatchPicker`（SF Symbol 色块，带朗读色名）。下钻行（标签 · 值 · ›）一律 `FormNavRow`、单选行（✓）一律 `FormCheckRow`（可选 `systemImage` + `systemImageColor` 数据色），不要手拼 HStack。SwiftUI 里嵌 RN 视图用 `RNHostView matchContents`，只放小岛，不放列表。**每个自己建的 `Host` 都加 `useLocaleEnv()` modifier**——SwiftUI 控件默认按设备语言格式化（zh 界面里出现 "Jun 1, 2026"）；它传 ICU id（`zh_Hans_CN` / `en_US`）——图形 DatePicker 不认 BCP-47 的 `zh-CN`（月份头仍是英文，iOS 26.5 实测）；`NativeForm` / `Segmented` / `EmptyState` / `NativeButton` 已内置。格式化日期用 `useLocale()` / `localeOf(lang)`（[src/lib/i18n](./src/lib/i18n)），不要各写一份 `'zh-CN' : 'en-US'`。
- **内容区按钮**：[src/ui/button.tsx](./src/ui/button.tsx) `NativeButton`（真 SwiftUI Button，accent 着色）——`variant="tinted"`（默认，`.bordered`，重试/恢复此版本这类次要动作）/ `"prominent"`（每屏唯一主动作：iOS 26 `.glassProminent`，旧系统 `.borderedProminent`）/ `"glass"`；`fullWidth`、`loading`、`destructive`、`size`。导航栏动作仍是 `Stack.Toolbar.Button`，Form 里的动作是 SwiftUI `Button`。不要再用 `Pressable + Text` 拼按钮。
- **列表**：内容型列表（分页、富行、标签）用 RN `FlatList/SectionList` + [src/ui/list.tsx](./src/ui/list.tsx)：`ListSection`/`ListRow`/`IconTile`（UIKit 几何：44pt 行、16pt 边距、分隔线缩进到文字、`fill` 按压高亮；`ListRow` 有 `subtitleLines`、`leading`+`leadingWidth`、`footer` 展开槽；没有 `onPress` 的行是普通可读 `View`、**不再**被读成「已停用」——只有显式 `disabled` 才是；包在 `Menu` 里当触发器的行传 `menuTrigger`（读作按钮），长按菜单里的动作同时经 `accessibilityActions`/`onAccessibilityAction` 给 VoiceOver）。**虚拟化列表**不能包 `ListSection`：每行传 `position`（`first`/`middle`/`last`/`only`）自己画分组卡片的那一片，段头/段尾用 `ListSectionHeader`/`ListSectionFooter`，自由内容卡片用 `ListCard`；自定义行布局沿用 `LIST_TILE` / `separatorInset()`。胶囊标签（状态、当前、分类）用 `Badge`（`tone` 系统色或 `color` 数据色），不要每屏重画。纯设置型列表用 SwiftUI `Form`。首次加载用 [src/ui/empty.tsx](./src/ui/empty.tsx) `LoadingState`（居中原生 spinner，不要手摆 `ActivityIndicator`）；空状态 / 无结果 / 加载失败用同文件 `EmptyState`（SwiftUI ContentUnavailableView；`onRetry` 给标准重试按钮，`action` 放任意 `NativeButton`）。注意 `contentInsetAdjustmentBehavior="automatic"` 的滚动视图里 `flexGrow + justifyContent:'center'` 是按整帧居中、不是按可见区——大标题页要补 `paddingBottom = headerHeight + 底部安全区`（见知识库列表）。下拉刷新用 RN `RefreshControl`（原生 UIRefreshControl，`tintColor={hex.accent}`）。分段切换用 [src/ui/segmented.tsx](./src/ui/segmented.tsx)。头像用 [src/ui/avatar.tsx](./src/ui/avatar.tsx) `InitialAvatar`（AI 的身份是 Sprouty，不用字母头像）。
- **链接与文件**：网页链接一律 [src/lib/links.ts](./src/lib/links.ts) `openLink(url, hex.accent)`——App 内 Safari（SFSafariViewController，`expo-web-browser`），mailto / tel 交给系统；**不要用 `Linking.openURL` 打开网页**（会把人甩出 App）。需要鉴权的服务端文件（`export_table` 结果 `/api/chat-files/<id>/content`；工具输出里的 `download_url` 先过 [src/chat/chat-file-url.ts](./src/chat/chat-file-url.ts) `chatFilePath`/`chatFileUrl`——只认本站这条相对路由，别的 URL 绝不带 token）用 [src/lib/share-file.ts](./src/lib/share-file.ts) `downloadAndShare(path, name)`：经 `api()`（带 token、401 透明刷新）下载到 cache，再交给系统分享表单（存到文件 / 隔空投送…），返回 false 时调用方 `alertError`。
- **搜索**：推入页用原生搜索栏（`Stack.SearchBar` / `headerSearchBarOptions`），不要页内自绘搜索框（抽屉顶部的搜索框例外）。
- **键盘**：RN 输入直接用 `react-native-keyboard-controller`：对话用 `KeyboardChatScrollView` + composer 包 `KeyboardStickyView`；RN 表单（知识库编辑器）用 `KeyboardAwareScrollView`；任务评论栏用 `useReanimatedKeyboardAnimation`；SwiftUI 表单不用管。不要用 RN 的 `KeyboardAvoidingView`。
- **触感**：原生控件自带；自定义控件只在有意义时给（发送 `tapLight`、选择变化 `selectionTick`），`Touchable` 默认无触感。
- **已知坑（实测）**：
  - `@expo/ui` 的 `MenuView` 默认按子元素**固有宽度**布局，长文本会溢出——`NativeMenu` 的 `fill`（longPress 默认开）量宽后把触发器钉到槽宽；代价：子树先裸渲染量宽、再挂进菜单宿主，**会挂载两次**（入场动画会重放——要动画的内容别在菜单出现的同一刻入场）。试过「子树一开始就放进宿主、之后再钉宽」：宿主内的 RN 子树只按固有宽度测一次，钉宽后文字不再重新折行（行内摘要变成一行溢出），已实测否决。
  - SwiftUI `Host` 内 RN 内容的点按（Pressable）可用；sheet 若不开原生 header，自绘 header 会和滚动内容重叠——用 `{ header: true }`。
  - 普通 RN 覆盖层画在根视图里，**在所有原生 sheet / modal 下面**——要盖过 sheet 的 UI（toast）必须用 react-native-screens 的 `FullWindowOverlay`，且只在显示时挂载（挂载时才被加到 window 最上层）。
  - 根 Stack 的 `initialRouteName` 是 `(drawer)`：深链页面下面总有首页。**重定向到首页不要用 `<Redirect>` / `router.replace`**（会在旧首页上再叠一个新的 `(drawer)`），用 `router.dismissTo('/…')` 或 `navigate`。
  - SwiftUI 控件的语言跟设备而不是 App——见上「表单」的 `useLocaleEnv()`。
  - **sheet 里的 SwiftUI Form 要从首帧挂载**（2026-10-08 在已删除的 `/bots/info` 实测）：先渲染 RN 加载态、数据到了再挂 `NativeForm` 的话，晚挂载的 `Host` 拿不到 sheet 导航栏的顶部内边距，第一个**无标题** Section 会钻到导航栏下面。做法：同一个 `NativeForm` 实例从第一帧就在（加载中放一行 `ProgressView` Section），数据到了只换它的 children；原生输入框照旧在数据就绪后才挂（它们只在挂载时取初值）。错误态可以留在 Form 外用 RN `EmptyState`。
  - **Form 里的输入框有焦点时不能删掉它所在的 section**（2026-10-08 实测）：UIKit 抛 `NSInternalInconsistencyException`（"first responder contained inside of a deleted section … refused to resign"）直接崩。会在关闭时换掉 Form children 的 sheet，在 `navigation.addListener('beforeRemove')` 里先 `Keyboard.dismiss()`。
  - **iOS 会把「普通 TextField + SecureField」当登录表单**：不给 content type 也一样，含已填 SecureField 的视图消失时弹「存储密码？」（会把第三方网站的账号存到 Greenhouse 名下）。代人登录别处的表单（`/bots/login`）要在 `beforeRemove` 里先清空字段再走。


## Android 规范（Material 3，2026-10 起支持）

目标与 iOS 一致——**像系统 App 一样原生**，只是系统换成 Material 3：Android 上的系统组件来自 `@expo/ui/jetpack-compose`（真 Compose）与 react-native-screens。**SwiftUI 组件在 Android 上一渲染就崩**（导入无害，只打警告），所以凡是渲染 `@expo/ui/swift-ui` 的模块都要有 Android 版。

- **平台拆分**：同名 `*.android.tsx` 兄弟文件（Metro 按平台挑），**扩展名必须与基础文件一致**（Metro 先试完所有 `.ts` 变体才试 `.tsx`——`dialogs.ts` + `dialogs.android.tsx` 会在 Android 上选中 iOS 版）。行为放共享 hook（`src/login/use-login.ts`、`src/settings/use-settings.ts`、`src/stations/use-stations-form.ts`、`src/chat/use-tag-library.ts` / `use-tag-editor.ts`、`src/projects/use-task-form.tsx` / `use-project-form.tsx`），两端只各写视图。路由也可以拆（`app/login.android.tsx`；不带后缀的 iOS 文件必须存在）。**Android 文件里导入平台兄弟模块要写全 `.android` 后缀**（`../src/ui/native-form.android`）——TypeScript 不认平台后缀，裸路径会按 iOS 版类型检查。**新增平台文件后要重启 Metro**（已缓存的解析不会失效）。
- **主题**：[src/theme-m3.android.ts](./src/theme-m3.android.ts) 用 `getMaterialColors({ seedColor: Haven })` 把 `colors.*` / `hex.*` 映射到 M3 色彩角色（surface / surfaceContainer / onSurface / outlineVariant / primary…）——和 Compose 组件用的是同一套调色板，品牌色优先于壁纸取色。Compose 岛一律用 [src/ui/m3.tsx](./src/ui/m3.tsx) 的 `M3Host`（同调色板 + App 内深浅色），取色用 `useM3()`；不要裸 `Host`。字体：`typo` 在 Android 上是 M3 字阶（正文 16/24）。
- **导航**：同一套 `nav.ts` 预设在 Android 上是不透明的 Material 顶栏（左对齐标题、onSurface 图标色）——内容从顶栏下方开始，手动偏移一律 `useHeaderInset()`（[src/ui/header-inset.ts](./src/ui/header-inset.ts)，iOS = 头高、Android = 0），**不要直接用 `useHeaderHeight()`**。`sheetScreen()` 在 Android 上是**全屏对话框**（自下滑入、顶栏 ✕ 代替 ←）——RNS 的 Android form sheet 不渲染头部，sheet 会丢标题与 ✕/✓。
- **表单 = Material**：[src/ui/native-form.android.tsx](./src/ui/native-form.android.tsx)——`NativeForm`（一个 Compose 岛 + `LazyColumn`）、`FormSection`（M3「连接式」列表：surfaceContainer 行、两端大圆角、行距 2dp、primary 色组标题、可 `footerError`）、行组件 `FormNavRow` / `FormCheckRow`（单选 = 尾部 RadioButton）/ `FormSwitchRow` / `FormSelectRow`（下拉菜单）/ `FormValueRow` / `FormSegmentedRow` / `FormActionRow`（破坏性用 error 色）/ `FormSwatchRow`（选中色带 ✓）、`FormTextField`（OutlinedTextField：浮动标签、supporting / error 文本、IME 动作、`autofill` 提示——Google 密码管理器能识别）。日期 = [src/projects/form-fields.android.tsx](./src/projects/form-fields.android.tsx)：开关 + Material 日期选择对话框（UTC 日 ↔ stamp，无时区偏移）。行的次要动作放**长按**（Android 没有左滑）。`FormChrome` 在 Android 上拦截系统返回：有未保存修改先确认放弃。
- **菜单**：[src/ui/menu.android.tsx](./src/ui/menu.android.tsx) `NativeMenu` 同 API——触发器保持纯 RN，靠 gesture-handler 的原生长按 / 点按识别（与行自身的 `onPress` 并存：点按照常打开，长按取消点按并弹菜单）；菜单本体只在根布局的 `MenuHost` 渲染一个 Compose `DropdownMenu`（长按 = 手指处，点按 = 触发器下沿）。**不要给列表行包 Compose 宿主**（虚拟化列表里的 Compose 岛可能永远不挂载，且每行一个很重）。分组之间有分隔线、子菜单就地展开、`title` 作菜单头。
- **对话框**：[src/ui/dialogs.android.tsx](./src/ui/dialogs.android.tsx) 同 API 的 Material 3 对话框（Compose `AlertDialog`：28dp 圆角、句首大写的文字按钮、破坏性用 error 色），根布局挂 `DialogHost`；`promptText()` 在 Android 上是带输出框的对话框（重命名可用）。**toast** = 系统 `ToastAndroid`；Android 13+ 系统会自己确认剪贴板写入，「已复制」不再重复提示。
- **其它约定**：内容区按钮 `NativeButton` → M3 Filled / Tonal / Elevated；分段控件 → M3 SegmentedButton；空状态 → Material 图标 + 标题 + 说明；`Glass` 退化为平的 tonal 表面（不要阴影——高度阴影会溢出圆形被方形裁切）；composer 在 Android 坐在实体底带上（内容不从它下面穿过）；列表组标题用 primary 色、句首大写。工具栏顺序：Android 的搜索按钮总在最右，所以与搜索并列的菜单用 `filter` 图标而不是 `⋮`。
- **验证**：Android 真机（dev client）`adb reverse tcp:8097 tcp:8097`（Metro）+ `tcp:3121`（本地 API）后 `exp+greenhouse-mobile://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8097` 拉起；`uiautomator dump` 在有持续动画的页面（首页 Sprouty 呼吸）会报 idle 超时，那里靠截图 + 坐标。发布包：`./gradlew :app:assembleRelease`（默认用 debug keystore 签名，可直接覆盖安装 debug 包）。

## 关键约束（容易踩坑）

- **不是 pnpm workspace 成员**。`pnpm-workspace.yaml` 用 `!apps/mobile` 显式排除——它的 React-19 / RN 依赖图若被 hoist 进共享 store 会污染 web/api 的 React 类型。
  - 安装：在本目录运行 `pnpm install --ignore-workspace`（或根目录 `pnpm mobile:install`），依赖全部落在 `apps/mobile/node_modules`，有自己的 `pnpm-lock.yaml`。
  - **不要用 `npx expo install` 装依赖**——它会绕过隔离、把 apps/mobile 作为 importer 写进**根** `pnpm-lock.yaml`（已踩过）。正确做法：手动在 package.json 里钉版本（SDK 57 的包一般是 `~57.x`），再 `pnpm install --ignore-workspace`。
  - **expo CLI 的自动依赖检查同样会泄漏**（已踩，2026-07）：`expo run:ios` 等命令会自己跑一次未隔离的 `pnpm install`，把部分符号链接重连到**根** store —— Metro 的 blockList 拦下后表现为真机红屏 `Unable to resolve "expo-status-bar"`（node_modules 混合指向，`readlink node_modules/<pkg>` 出现 `../../../node_modules/.pnpm` 即中招）。隔离屏障 = 本目录自己的 [pnpm-workspace.yaml](./pnpm-workspace.yaml)（pnpm 向上查找先命中它，裸 `pnpm install` 也是 standalone）；**不要用项目级 `.npmrc` 承载 pnpm 配置——pnpm 11 不读它**（历史上的 `node-linker=hoisted` 就一直没生效，实际布局是 isolated symlink，Metro 兼容）。若再泄漏：`rm -rf node_modules && pnpm install` 重建 + `expo start --clear`。
  - 不要 `import '@greenhouse/types'` 等 workspace 包。需要的类型在 [src/shared/greenhouse-types.ts](./src/shared/greenhouse-types.ts) 里 **vendored**（复制子集，头注释指向 canonical 源 `packages/types/src/api.ts`）。服务端形状变了要同步改这里。
  - **TODO（待办）**：letpot 的 `packages/contract/src/mobile-parity.ts` 是现成模板，可加同款 CI 绊网把 vendored 类型与真相做可赋值断言，防漂移。（植物头像已有同类绊网：`src/ui/plant-avatar/plant-avatar.parity.test.ts`，跑在根 vitest。）
  - **Metro 也要隔离**：[metro.config.js](./metro.config.js) 用 `resolver.blockList` 屏蔽**仓库根** `node_modules`，否则 Metro 的逐层向上查找会捞到泄漏的重复依赖（曾致 `react-native-worklets` 原生/JS 版本不匹配）。新增原生模块若报 "version mismatch"，先查根 `node_modules` 泄漏。
- **`react-native-webview`（13.16.1，SDK 57 钉的版本）是原生依赖**：只给 ```mermaid 图示与 ```html-preview 预览用。加/升级它 = 新二进制（fingerprint 变，不能 OTA）。mermaid 本体不打进包：从 CDN 按 `MERMAID`（`markdown/blocks/mermaid.tsx`：版本 + sha384）加载，**升级 mermaid 要同时改版本和 SRI**（`openssl dgst -sha384 -binary mermaid.min.js | openssl base64 -A`，jsDelivr / npmmirror 字节相同）。
- **`pod install` 之后预编译产物的 flavor 标记可能和实际解压的不一致**（2026-10-07 踩）：`Pods/React-Core-prebuilt`、`Pods/ReactNativeDependencies`、Hermes、`Pods/Expo*/artifacts` 各自靠 `.last_build_configuration` 判断要不要换 Debug/Release 包；pod install 重建目录后标记缺失或残留 → Debug 构建链接报 `typeinfo for facebook::react::BaseViewProps` 缺失，或启动即 SIGSEGV 在 `facebook::react::Props::Props()`（ExpoModulesCore 预编译包与 React core flavor 不符）。修法：把这些标记都写成**相反**的配置（React core / RNDeps / Hermes 写 `Release`、`Expo*/artifacts/.last_build_configuration` 与 `ExpoImage/artifacts/*.last_config` 写 `release`），下一次 Debug 构建就会全部重新解压；打 Release 前反过来。
- **运行中改系统字号，已挂载的文字不重排**是 RN 0.86 iOS 的 bug（Fabric 在主线程克隆节点重测，React 的引用没跟过去，下一次渲染把旧节点放回，Yoga 复用旧测量；facebook/react-native#57512），不是本应用缓存。OTA 可用的绕法：无状态的文字容器（行、气泡、卡片头 / 体、说明行）用 [src/ui/font-scale.ts](./src/ui/font-scale.ts) `useFontScaleKey()` 当 `key`，字号变了就重挂重测；**不要**给屏幕 / 列表 / 导航器 / 表单加（会丢草稿、滚动位置、导航状态）。新写的行组件照此办理。
- **iOS 模拟器验收的坑（2026-10-08 Bots 验收踩）**：① `pod install` 偶发**静默退回源码构建 RN core**（日志 `[ReactNativeCore] No prebuilt artifacts found`，查 maven 超时）→ 预编译的 Expo 模块启动即 dyld `Library not loaded: @rpath/React.framework`（SpringBoard 只记 exit `dyld code 1`，`xcrun simctl launch --console-pty` 才看得到）→ 重跑 `pod install` 确认 `Building from source: false` 再编。② dev client 右上角浮动的「Tools」齿轮会**盖住 sheet 工具栏的 ✓**，点 ✓ 实际打开 dev 菜单——在 dev 菜单里关掉 "Tools button"。③ XCUITest 会话**结束（teardown）时常把 App 弄崩**（SIGSEGV，无崩溃报告，非产品代码）：驱动保持一个常驻会话循环读步骤，而不是每批起一个 `xcodebuild test`。④ 有文件在改时 Metro 热重载会把 App 状态冲回首页，别在并行改代码时做交互验收。⑤ Metro 用 `CI=1` 起会关掉 watch，还可能拿旧文件映射（`Unable to resolve expo-router/entry`）——去掉 `CI`、`--clear` 重启。
- **原生工程不入库**。`/android`、`/ios` 由 `expo prebuild`（CNG）生成，已在 `.gitignore`。`expo prebuild --clean` 会清掉 `android/local.properties`，真机构建前需补 `sdk.dir`（或导出 `ANDROID_HOME`）。
- **打包/Release Android 构建两坑（首次跑 release APK 踩，2026-07-04）**：`expo run:android` 的 **debug** 变体不打包 JS（真机从 Metro 取），所以这两坑只在**打包构建**（`gradlew :app:assembleRelease` / 独立可离线跑的 release APK）暴露：
  1. **`babel-preset-expo` 必须是直接依赖**。[babel.config.js](./babel.config.js) 用裸字符串 `'babel-preset-expo'`，pnpm isolated 布局不把这个传递依赖 hoist 到顶层 `node_modules` → 打包步 `:app:createBundleReleaseJsAndAssets`（`expo export:embed`）报 `Cannot find module 'babel-preset-expo'`。已按「手动钉版本」约定加进 devDependencies（`~57.0.13`，随 SDK 57）。
  2. **HTTP LAN API 要放行 cleartext**。targetSdk≥28 下 release 默认禁明文 → 打到 `http://<lan>:4401` 的请求全部失败（debug 有 `android/app/src/debug/AndroidManifest.xml` 豁免，故只 release 中招）。**已用 `expo-build-properties` 插件固化**（app.json：`android.usesCleartextTraffic: true`，prebuild 自动写入 manifest）——重跑过 `pnpm mobile:prebuild` 之后不需要再手改；改动此插件配置后记得重跑 prebuild。release 默认用 **debug keystore** 签名（`signingConfigs.debug`），与 dev client 同签名，可直接 `adb install -r` 覆盖装机、不丢 SecureStore 登录态。
- **Expo Go 跑不了**：`expo-secure-store` / `react-native-keyboard-controller` 需要 dev client（`pnpm mobile:ios` / `pnpm mobile:android` 构建）。UI 以 **iOS 模拟器 / Android 真机（dev client）为准**——SwiftUI / Compose 表单、原生 sheet、系统菜单、Liquid Glass 在 Expo web 上不存在或只是降级，`pnpm mobile:web` 只适合看数据层与纯 RN 内容。
- **`.env` 不入库**。工作站（station）配置由本目录 [greenhouse.config.ts](./greenhouse.config.ts) 从 `EXPO_PUBLIC_*` env 组装——对应根 `greenhouse.config.ts` 的 `clients.stations`（类型 vendored 在 [src/shared/greenhouse-config.ts](./src/shared/greenhouse-config.ts)），经 [src/config.ts](./src/config.ts) 暴露为 `STATIONS` / `IS_SINGLE_STATION`（旧的 `DEFAULT_API_BASE` / `HAS_PINNED_BASE` 由此派生）。三个 env：
  - `EXPO_PUBLIC_API_BASE_URL`（可选）：默认工作站的 origin，设了就是 `STATIONS.defaults` 的唯一一项，首启种进注册表（未登录）——它只是**首启种子**、不硬编码 API 地址。不设 → 通用商店构建，首启为空列表、由用户自己添加服务器（`__DEV__` 下仍种 `http://localhost:3000`；Android 模拟器用 `10.0.2.2:3000`，真机用 Mac 的 LAN IP）。
  - `EXPO_PUBLIC_STATION_NAME`（可选）：默认工作站的显示名，缺省为 host。
  - `EXPO_PUBLIC_STATIONS_MODE`：`multi`（默认，用户可添加/切换）或 `single`（**锁定**到默认工作站：`hydrate()` 每次把注册表收敛为只剩它——同 origin 的旧条目保留 id 与 token，其余连 token 一起清掉；`add`/`switchTo`/`remove` 忽略；`StationsForm` 只显示它、隐藏添加与移除，登录页 / 设置的工作站行照常打开，可看当前服务器）。`single` 而没设 URL、或 mode 值未知，会在 import 时抛错（fail closed）。
- **Expo web 开发要给 API 配 CORS**：API 的 CORS 是白名单制（`CORS_ALLOWED_ORIGINS` env）。本地跑 `pnpm mobile:web`（8081 端口）时启动 API 要带 `CORS_ALLOWED_ORIGINS=http://localhost:8081`。原生 app 无 Origin 头，不受影响。

  - 关键配置：`app.json` `runtimeVersion.policy: "fingerprint"`（OTA 只投给指纹兼容的二进制，杜绝不兼容热更）；`eas.json` `appVersionSource: "remote"`（`buildNumber`/`versionCode` 在 EAS 云端自增——CI 的 checkout 是一次性的，local 自增会丢）；`expo-updates` 已装（CNG prebuild 自动应用其 config plugin，无需手动进 plugins 数组）。已知 gotcha：`eas init`/`eas build` 触发的 @bacons/apple-targets 同步会把 widget 的 App Group **重复追加**进主 app 的 `ios.entitlements`（不去重）——提交 app.json 前手动 dedupe 回单条。
  - 一次性开通（secret-gated，见 RELEASING.md 步骤 1–5）：`eas init` + `eas update:configure`（回填 `projectId`/`updates.url` 后提交）→ 本地跑一次 `eas build --profile production --auto-submit` 播种凭据/ASC app/远端 build 号 → Expo dashboard 配 `EXPO_PUBLIC_API_BASE_URL`（构建期烘焙,workspace-picker 登录落地前的过渡）→ 仓库加 `EXPO_TOKEN` secret。
  - 测试者拿包：workflow_dispatch 选 `preview`，或本地 `eas build --profile preview`（离线替代仍是本目录 AGENTS 记的 `gradlew :app:assembleRelease` 本地通道）。

## Haven 品牌资源与启动

- 图标与 `src/ui/brand.generated.ts` 由根目录 `scripts/build-brand-assets.py` 从共享 SVG 生成，不能手改几何；规范见 [logos/README.md](../../logos/README.md)。
- 开屏（[src/ui/splash.tsx](./src/ui/splash.tsx)）：根布局在 auth 与字体就绪后就挂路由，`<Splash/>` 盖在上面，`GreenhouseMark` 完整搭一遍（`MARK_BUILD_MS` 1.8 s）+ 停 150 ms 再 200 ms 淡出——**一定播完**（2026-10：登录快时会被截断在半途）；系统减少动态效果时标志静态、就绪即走。原生 launch screen 是空白的系统背景色（CNG 生成、跟随深浅色），JS 开屏从空白开始搭，衔接无跳变——不要给原生 launch screen 加静态标志（会先出现、消失、再被搭一遍）。
- Mermaid 的普通矩形节点/时序参与者框使用 `radius.md`；WebView 从生成的 `brand-web-font.generated.ts` 内置 Nunito WOFF2，并等待字体就绪后布局。与原生文字共享字体源，不依赖额外字体网络请求。
- 修改 app icon 或 expo-font 插件后需重新构建 native binary；OTA 无法更新系统图标/字体注册。

- 登录成功后的首页跳转只由根布局 auth gate 执行；共享 `useLogin` 仅提交认证并显示失败原因，不重复 `router.replace`，避免更新已卸载的原生导航头。
