# apps/mobile: Expo app (iOS system UI first, Material 3 on Android)

## Install and tests

- apps/mobile is outside the pnpm workspace with its own lockfile: install with `pnpm mobile:install`, and run `pnpm typecheck` and `pnpm lint` inside apps/mobile, because root checks and CI skip it.
- Never run `npx expo install`; it writes apps/mobile into the root pnpm-lock.yaml. Pin versions by hand (SDK 57 packages are ~57.x), then run `pnpm mobile:install`.
- apps/mobile/pnpm-workspace.yaml is the isolation barrier; pnpm 11 ignores .npmrc, so never put pnpm settings there.
- If packages get relinked into the root store (metro.config.js blocks it: red screen "Unable to resolve" or a native "version mismatch"; `readlink node_modules/<pkg>` shows ../../../node_modules/.pnpm), delete node_modules, run `pnpm mobile:install`, then `expo start --clear`.
- Never add `@react-navigation/*` (expo-router vendors it); keep react-native-drawer-layout and babel-preset-expo as direct dependencies.
- Never import `@greenhouse/*` packages. Files headed VENDORED are copies: re-copy them from the canonical source instead of editing (the `*.parity.test.ts` files fail on drift), and update hand-kept subsets such as src/shared/greenhouse-types.ts when the server shape changes.
- The root vitest runs mobile tests without a mobile install: tests must not import react, react-native or `expo-*`, even transitively; move logic into React-free modules and check by moving apps/mobile/node_modules aside.
- Tests and the modules they import must sit in directories with a stub tsconfig.json (copy src/api/tsconfig.json), or CI fails with TSConfckParseError.

## Native builds and release

- ios/ and android/ are generated by `pnpm mobile:prebuild` and git-ignored; rerun it after changing app.json, plugins, entitlements or targets/, then restore sdk.dir (or ANDROID_HOME), since --clean deletes android/local.properties.
- Expo Go cannot run the app; use a dev client (`pnpm mobile:ios`, `pnpm mobile:android`) and judge UI on the iOS simulator or an Android device, never on Expo web.
- Expo web (`pnpm mobile:web`, port 8081) needs the API started with CORS_ALLOWED_ORIGINS=http://localhost:8081.
- Releases follow the native fingerprint: JS-only changes ship as OTA; native changes (native modules such as react-native-webview, new ICONS entries, app icon, fonts, entitlements, app.json, widget Swift or PNGs) need an EAS build. Runbook: RELEASING.md.
- Never hand-edit the version in app.json or package.json; release-please bumps it and fingerprint.config.js keeps it out of the fingerprint.
- eas init and eas build can append a duplicate App Group to ios.entitlements (@bacons/apple-targets); dedupe it before committing app.json.
- iOS status bars are owned by native controllers (`UIViewControllerBasedStatusBarAppearance=true`); all stacks pass the app theme to stackDefaults. Expo StatusBar is Android-only.
- Native development is verified with local dev-client builds on dedicated simulators. Release signing follows RELEASING.md; do not publish during development.
- After pod install, stale .last_build_configuration flavor markers cause Debug link errors (BaseViewProps typeinfo) or a launch SIGSEGV in Props::Props(); write the opposite configuration into the markers so the next build re-extracts.
- pod install can silently fall back to building React Native from source ("No prebuilt artifacts found") and crash at launch on React.framework; rerun it until it reports "Building from source: false".
- Mermaid loads from a CDN with SRI: change version and sha384 together in MERMAID (src/chat/markdown/blocks/mermaid.tsx).

## UI

- Use system components: the expo-router native Stack, @expo/ui/swift-ui and NativeMenu (src/ui/menu.tsx; pass width when it is known to skip the measuring remount); never JS-drawn headers, bottom sheets, action sheets, calendars or switches.
- Glass (src/ui/glass.tsx) is for the control layer only (bars, toolbars, floating buttons, composer); content sits on solid system colors; group adjacent glass in GlassGroup, never glass on glass.
- `colors.*` are PlatformColor objects: never concatenate or compute alpha on them; use `hex.*` for strings and alpha() for transparency.
- Text and icons on the accent use onAccent, on other solid fills onTint; no hex literals except data colors.
- Take typo, weight, radius (with squircle) and HIT from src/theme.ts; never disable allowFontScaling.
- Register icons as [SF Symbol, Material] pairs in ICONS (src/ui/core.tsx) and run `python3 scripts/android-icons.py` in apps/mobile; toolbar icons go through toolbarIcon().
- Give every icon-only button an accessibilityLabel; Icon is hidden from VoiceOver unless it stands alone.
- Declare presentation only in app/\_layout.tsx with the src/ui/nav.ts presets; screens set their own title and toolbar; the back button is always the system's.
- Sheets are routes; take their chrome from src/ui/sheet-chrome.tsx (SheetClose, FormChrome, useLeaveSheetTo, which dismisses before pushing).
- Pass structured params with putHandoff (src/lib/handoff.ts), read with the matching kind and handle an expired key; return results through a zustand store, never callbacks.
- SheetActions owns pinned bottom actions through SheetFrame; the partial-height fade covers only the scrolling body. Primary actions are full-width; FormChrome retains close/back draft guards.
- A failed user action shows alertError (raw provider text goes in detail); toast is for success only; a failed load shows EmptyState with retry; login errors stay inline.
- Forms use NativeForm with FormNavRow and FormCheckRow; content buttons use NativeButton, never Pressable plus Text.
- Every SwiftUI Host you create gets the useLocaleEnv() modifier, and inline hosts in RN content get ignoreSafeArea="all"; format dates with useLocale() or localeOf().
- Lists use src/ui/list.tsx; virtualized rows pass position instead of sitting in ListSection; show LoadingState and EmptyState.
- Open web pages with openLink() (in-app Safari), never Linking.openURL; file bytes use signed /api/files links; api() attaches tokens only to the active station origin.
- Use the native search bar (Stack.SearchBar) and react-native-keyboard-controller; never KeyboardAvoidingView.

## Native pitfalls

- RN overlays render below native sheets: UI that must cover them (toast) uses FullWindowOverlay, mounted only while shown.
- The root Stack starts at (drawer) and threads live on the home route (/?c=): go home with router.dismissTo or navigate using homeParams() (src/shell/nav.ts), never `<Redirect>`, router.replace or a sibling screen under (main).
- Mount a SwiftUI Form in a sheet on the first frame and swap its children when data arrives, or its first untitled Section slides under the nav bar; never nest Sections in a DisclosureGroup.
- Never remove a Form section while one of its inputs has focus (UIKit crash); call Keyboard.dismiss() in beforeRemove.
- iOS treats a TextField plus SecureField as a login and offers to save the password; clear such fields in beforeRemove when the form signs in elsewhere.
- Changing the system font size at runtime does not relayout (RN 0.86 bug): key stateless text containers with useFontScaleKey(), never screens, lists, navigators or forms.
- Hermes rejects Postgres timestamps; parse them with parseMs() (src/data/time.ts).
- Android Intl may have only English locale data; calendarDateLabel uses the date dictionary and member time zone, preserving date-only values.
- Only the root layout's auth gate navigates on sign-in and sign-out (routes reachable signed out go in SIGNED_OUT_ROUTES); startup readiness may hold the splash but never block route mounting.

## Android

- Rendering @expo/ui/swift-ui crashes on Android: every module that renders it needs a `*.android.tsx` sibling with the same extension as its base file, with behavior in a shared hook.
- Android files import platform siblings with the explicit .android suffix; restart Metro after adding a platform file.
- SDK 57 Compose ObservableState ids fail in text-field value props on Android. text-state.android.ts mirrors input/AutoFill and applies initial values after native layout, then explicit changes through TextFieldRef; import useNativeState from native-form.android, never directly from Expo UI.
- Compose islands use M3Host (src/ui/m3.tsx), never a bare Host; never wrap list rows in Compose hosts.
- Offset content with useHeaderInset(), never useHeaderHeight().
- WebView passes iOS-only props through Android Fabric too: pass dataDetectorTypes as an array, never a string.
- Conversation, knowledge, tables and apps run on both platforms; entries follow me.modules.

## Data, i18n and widgets

- API reads return null or a discriminated miss on failure; writes return booleans or results and never throw; resolve the base with getApiBase() at call time.
- Call the API through api() (src/api/client.ts), which sends tokens only to the active station; switch stations only with useAuth.switchStation.
- Station defaults come from EXPO_PUBLIC_STATIONS_MODE, EXPO_PUBLIC_API_BASE_URL and EXPO_PUBLIC_STATION_NAME (apps/mobile/greenhouse.config.ts); a single-mode build without a URL must throw at import.
- en.ts is the key source and zh must match; delete unused keys after searching dynamic prefixes (`tools.*`, `sourceCat.*`).
- A snapshot schema change in src/widget/model.ts must update the Swift Snapshot in targets/widget/index.swift, bump SNAPSHOT_VERSION and supportedSnapshotVersion, and keep new Swift fields optional.
- Never add widgetAccentedRenderingMode to images inside a widget Link, and keep accessibility modifiers on the Link label; both break the tap target.
- Never hand-edit widget PNGs; rerun `node --import tsx apps/mobile/scripts/render-widget-art.mjs` from the repo root.
- Live Activities: keep the two BotTaskAttributes.swift copies identical and NSSupportsLiveActivities in app.json, encode times as integer Unix seconds, and keep images no larger than their display size.
- Never commit development: true in getExpoPushTokenAsync; simulator push payloads put PushData under the top-level body key.

- message.resumed clears unfinished live text and truncates only a streaming cached reply to the
  completed offset. Keep the generated contract and realtime parser in sync when adding events.

## API v2 modules

- app/knowledge: spaces and folders, native Markdown reading and editing, versions, member mentions in comments, sharing and signed file previews. Docs, versions and comments use Markdown safe mode: executable rich previews remain code.
- app/tables: bases and views, phone record lists with a grid switch, kanban, agenda and a read-only timeline. Record and form routes are native sheets; computed fields are read-only.
- Doc edits keep the starting version; record edits keep the revision and send only changed values. Conflicts retain the draft and require explicit reload; never retry silently against a newer version. Failed reloads keep the draft.
- src/data/use-resource.ts owns focused-screen reads, relevant realtime invalidations and reconnect catch-up; late answers after focus or identity changes are dropped. Keep dirty drafts separate from refreshed server data.
- Root layout uses Expo fetch for multipart Files so they send bytes, retaining native fetch for JSON requests. Unit tests retain the default transport and require no native install.
- Root screen content is keyed by station/member identity so private sheets and drafts cannot survive an account switch. Keep the navigator mounted: remounting it breaks Android focus; theme and font size never change the content key.
- src/voice: configured STT records into the composer without sending; read-aloud uses configured TTS or device speech. Cancel when leaving or backgrounding; never speak raw rich JSON.
- Agent mail is owner-only. Mail cards open native sheets; show plain text, never untrusted HTML or automatic remote images. Release only verified mail held for an unknown sender.
- Homebrew Ruby may inherit incompatible RVM gem paths: run pod install with GEM_HOME/GEM_PATH unset and confirm Building from source: false.

## Latest v2 integration

- App runtime reads and writes use /api/apps with the pinned publication version; never open app records through the broader tables routes. Only published apps are listed; building stays on web and custom HTML stays disabled.
- App detail_fields is an explicit boundary, including an empty list. Forms retain drafts on stale_version; only explicit reload adopts another publication.
- Standing approvals are opt-in per tier2 card; tier3 never offers them. Disable approval while batch_ready is false. Receipts expose Undo only to the acting member, through the server revision checks.
- Agent owners manage schedules (quiet defaults off; edit only changed fields) and standing approvals. Keep approval selections and form drafts scoped to their request/object; discard late results after identity or route changes.
- Record handoffs leave the record sheet before opening the native brief form; completion opens its run. Helper runs have no direct retry. Event messages remain quiet lines in threads.
- App relation pickers read only published record cards that expose their title field, with that card's filter. If none exists, offer web completion; never fall back to ordinary table-title queries. Member choices use the member directory.

- Regenerate src/shared/contract.ts after computer/app contract changes. Queued computers keep polling. External app cards currently use the web fallback; custom HTML remains disabled on native.

## Phone parity

- DirectorySearch owns loaded-name filtering and clears it on blur; keep knowledge full-text search separate. Match names, never internal ids. Module navigation also clears the conversation drawer query.
- Skill directory selections fill a new composer without sending. Clear composer handoffs with station/member changes.
- Agent usage and budgets come from the owner's usage projection; memory uses the same member-scoped service as web.
- Read /api/me/operations for member-facing pause messages; only admins change switches. Queued computers poll only while focused and never offer another start. Do not fetch computer files/processes before running.
- Approval copy uses payload.summary/details from the permission-checked server projection. Never render execution inputs or standing-approval scopes as display copy.
- ListSection takes direct rows (arrays are fine), not a Fragment: it passes last to each child. Large text wraps row values and card headings without remounting screen state.

- Shared-note create/edit uses the note route and native multiline forms, never a global Alert.prompt: incoming links must not leave an editor over another screen. Guard saves and late feedback by focus and identity.

- Approval Markdown previews use inert preview mode: no links, images or executable rich blocks; clamp long content with expand. Receipts display the server message content verbatim. All dictionary interpolation uses the verbatim copy of packages/utils/src/i18n.ts in src/lib/i18n/format.ts, guarded by vendor.parity.test.ts. It adds a space at Han/Latin-or-digit boundaries even when templates omit it, and removes spaces between Han runs.
- Map operation_disabled plus details.switch through operationErrorText; never show the server's English pause copy as a member-facing reason.

- Run findings, summaries, briefs, output and completion reports use Markdown safe mode with native app links. Notification, schedule-list and request-card excerpts use plainText; approval previews stay inert. Memory rule errors map by code through operationErrorText. These display changes require no native modules.

- Agent author rows are room-only and sit above full-width replies. Thinking never adds an avatar. Replies expose a small NativeMenu; chat Markdown passes calm, while knowledge documents retain their type hierarchy.
- A one-field ask_user choice with 1–6 options answers in the card; all other questions keep the request route. Disable choices during the write, show the optimistic pick, restore on failure and read persisted selection from result.answers. Do not change request lifecycle rules for presentation.
- Readable custom light colors live in src/theme/palette.ts; theme.ts maps them to native dynamic colors while retaining system dark backgrounds. Keep contrast tests React-free.
- Message reactions are small emoji chips; todo plans render on the reply and run detail. One-off reminder pushes use the existing conversation target and replies category; generated files reuse MessageFiles and signed downloads.

- Notifications have one list and an unread badge; pending requests belong to their conversations. notification.removed clears request pointers on open screens. Superseded/withdrawn cards collapse and replacements open the new card in its source conversation.
